# Integration-проверки

Проверки запланированы для будущего сервиса. В учебных материалах нет исполняемого приложения, поэтому подтверждение означает **критерий проверки**, а не результат запуска.

| Связь компонентов | Что может сломаться | Как воспроизводим | Ожидаемый результат | Подтверждение |
|---|---|---|---|---|
| HTTP API → валидатор | Пустой payload доходит до сервиса и вызывает KeyError | POST /api/reviews с {} через TestClient, mock LLM считает вызовы | Ответ 4xx с указанием diff; 0 вызовов LLM | Статус, тело ответа, счётчик mock |
| HTTP API → сервис | Тип/размер diff не проверены | POST с числом и с текстом сверх лимита | Запрос отклонён до LLM | Статус 4xx и 0 вызовов |
| Сервис → LLM | Контекст не передан либо diff изменён | Fake LLM записывает prompt для учебного diff | Prompt содержит неизменённый diff и версию Context Pack | Сравнение записанного prompt с входом |
| LLM → проверка ответа | Модель выдала один корректный и один неверный риск | Fake LLM возвращает ссылки app/api.py:10 и app/api.py:999 | Корректный риск остаётся, неверный исключён с видимой причиной | Разбор ответа и сверка с diff |
| LLM → проверка ответа | Все ссылки неверны либо ответ неразбираем | Fake LLM возвращает только app/api.py:999; затем произвольный текст | В первом случае показана неопределённость; во втором — контролируемая ошибка | Два отдельных прогона fake LLM, проверка статуса результата |
| LLM → API | Таймаут или ошибка провайдера | Fake LLM выбрасывает timeout/exception | Контролируемый ответ без выдуманного ревью | Статус, тело, отсутствие успешного результата |

Код HTTP-ошибки при таймауте нужно утвердить в контракте до реализации; таблица не приписывает текущему diff несуществующую обработку.

## Как использовали AI

- Для чего: найти границы между компонентами и определить наблюдаемое подтверждение.
- Тип промпта: master prompting; [P1-03](prompts.md#журнал).
- Проверка: тесты покрывают переходы [схемы](adr.md#архитектурная-схема); исполнения и оценки студента пока нет.
