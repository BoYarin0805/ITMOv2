# Проблема и метрики

## Проблема

- **Пользователь:** человек, ревьюящий PR в учебном сценарии.
- **Ситуация:** поступает diff; ревьюеру нужно быстро понять изменение, найти проверяемые риски и выбрать тесты.
- **AS IS:** по принятой для кейса гипотезе человек выполняет первый проход вручную. Данных о времени и качестве текущего процесса нет.
- **Почему мешает:** поиск замечаний с доказательствами занимает время; общие советы трудно проверить. Это гипотеза для пилота, а не измеренный факт.
- **Задача:** предоставить человеку черновик ревью с доказательствами, сохранив за ним решение.
- **Вне задачи:** автоматический approve/merge, изменение кода, замена человека при ревью, вывод о безопасности всего репозитория по одному diff.

## Метрики

Цели ниже — **предложения для пилота**, а не текущие показатели. Перед пилотом нужно замерить базу на одинаковой выборке PR.

| Метрика | База и способ замера | Цель пилота | Когда измеряем | Источник данных |
|---|---|---|---|---|
| Время до первого полезного замечания | Медиана минут от открытия diff до замечания с местом и проверкой; база неизвестна | Снижение медианы ≥20% относительно ручного процесса | После 20–30 парных ревью | Таймстемпы эксперимента |
| Доля доказанных замечаний | Замечания с верным файлом, строкой и причиной / все замечания; база неизвестна | ≥90% | После 20 PR | Слепая разметка двух ревьюеров |
| Доля воспроизводимых проверок | Проверки, которые независимый инженер может исполнить / все предложенные; база неизвестна | ≥80% | После 20 PR | Протокол воспроизведения |
| Соблюдение границ | Случаи approve/merge/edit и утверждений о неисполненных тестах | 0 случаев | Каждый прогон | Логи ответа и аудит действий |

## Почему изменение метрики подтвердит решение проблемы

Экономия времени без доказательности создаст дополнительную работу, поэтому время оценивается вместе с качеством. Доля доказанных замечаний проверяет полезность первого прохода; доля воспроизводимых проверок показывает, может ли инженер действовать по ответу. Нулевое нарушение границ сохраняет решение за человеком. Эти метрики сами по себе не доказывают снижение дефектов в продакшене.

## Как использовали AI

- Для чего: сформулировать проблему и измеримый план пилота.
- Тип промпта: master prompting; [P1-03](prompts.md#журнал).
- Проверка: цели помечены как гипотезы; фактических замеров и оценки студента ещё нет.
