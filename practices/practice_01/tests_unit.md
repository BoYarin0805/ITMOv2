# Unit-проверки

Это **план тестов будущего прототипа** из [ADR-001](adr.md). Реализации валидатора и парсера в учебном diff нет; результаты ниже не выдаются за пройденные тесты.

| Требование или правило | Что проверяем изолированно | Вход | Ожидаемый результат | Подтверждение |
|---|---|---|---|---|
| Обязательный diff | Валидатор запроса | Пустой JSON | Ошибка о поле diff; LLM не вызывается | Unit-тест с mock LLM, ожидаемый статус после согласования контракта |
| Строковый непустой diff | Валидатор запроса | diff = 42; diff = пустая строка | Оба входа отклонены | Параметризованный unit-тест |
| Предел входа | Валидатор размера | Текст на границе лимита и на 1 байт больше | Первый допускается, второй отклоняется до вызова LLM | Тест граничных значений; сам лимит ещё утверждается |
| Не более трёх рисков | Проверка ответа модели | 4 структурированных риска | В итоговом черновике не более 3; избыток фиксируется как ошибка/отсечение по согласованному правилу | Unit-тест парсера |
| Доказательная ссылка | Проверка ссылки на diff | Риск для отсутствующей строки app/api.py:999 | Риск не выдаётся как подтверждённый | Unit-тест на подготовленном diff |
| Отказ модели | Обработчик исключений | Mock LLM выбрасывает исключение | Контролируемая ошибка; нет текста успешного ревью | Unit-тест сервиса |

Текущий учебный diff уже позволяет статически увидеть отсутствие проверки поля: app/api.py:10 обращается к payload["diff"]. Unit-тесты относятся к предложенному исправлению, а не к существующему репозиторию.

## Как использовали AI

- Для чего: вывести из контракта граничные случаи и ожидаемые результаты.
- Тип промпта: master prompting; [P1-03](prompts.md#журнал).
- Проверка: сценарии сопоставлены с [UC-1](product_management.md#use-case-uc-1-получить-черновик-ревью); фактический прогон не выполнялся, оценка студента не получена.
