# E2E-проверки

Проверки относятся к будущему рабочему сценарию. Для повторяемости в автоматическом E2E используется фиксированный ответ fake LLM; затем человек отдельно оценивает вывод реальной модели. Существующий учебный diff не содержит полного приложения для запуска этих сценариев.

| Сценарий пользователя | Предусловия | Действие | Наблюдаемый результат | Подтверждение |
|---|---|---|---|---|
| Позитивный | Сервис запущен, fake LLM возвращает структурированный ответ; TRAINING_PR.diff доступен | Ревьюер отправляет diff на POST /api/reviews | Описание изменения, ≤3 риска с реальными строками diff и проверки; никаких действий с PR | HTTP-ответ, сверка ссылок с diff, аудит действий |
| Негативный | Сервис запущен | Ревьюер отправляет {} | 4xx с сообщением о diff; LLM не вызвана | HTTP-ответ и счётчик вызовов |
| Граничный | Лимит diff согласован | Отправить текст ровно на лимите и на 1 байт больше | Граничный вход обрабатывается, сверхлимитный даёт 4xx до LLM | Два HTTP-ответа и счётчик |
| Сбой модели | Fake LLM возвращает таймаут | Отправить валидный diff | Контролируемая ошибка; нет ложного успешного ревью | HTTP-ответ и логи |
| Решение человека | Черновик показан ревьюеру | Ревьюер отклоняет ложное замечание | Решение/изменение PR выполняет только человек | Журнал действий PR |

После реализации пример команды для проверки: запустить сервис в тестовом окружении, затем прогнать HTTP-сценарии с фиксированными входами и сохранить отчёт. Точный исполняемый скрипт появится вместе с кодом прототипа.

## Как использовали AI

- Для чего: проверить сквозной путь и границу решения человека.
- Тип промпта: master prompting; [P1-03](prompts.md#журнал).
- Проверка: ожидаемые результаты следуют из [Gherkin](product_management.md#user-stories-и-acceptance-criteria); фактического прогона и оценки студента нет.
