# ReAct

- Цель: проверить, что новое правило частичного отбора риска из UC-1 согласовано с ADR и планами тестов.
- Доступные входы: локальные [product_management.md](../../practice_01/product_management.md#ошибки-входа-и-результата), [ADR](../../practice_01/adr.md#решение), [unit](../../practice_01/tests_unit.md#unit-проверки), [integration](../../practice_01/tests_integration.md#integration-проверки), [E2E](../../practice_01/tests_e2e.md#e2e-проверки), [TRAINING_PR.diff](../../practice_01/TRAINING_PR.diff).
- Разрешённые действия: читать локальные файлы, искать `rg`, исправлять планы тестов и ADR, запускать `git diff --check` и `make step2`.
- Запрещённые действия: запускать отсутствующее приложение, считать плановые тесты пройденными, менять учебный diff, отправлять действия в GitHub.
- Максимальное число шагов: 5 действий с наблюдением.
- Условие остановки и вопроса человеку: остановиться после успешной проверки структуры и согласованности; спросить человека только если нужен выбор точного HTTP-кода или лимита размера, которых нет в источниках.

## Запрос

> Работай циклом «действие → наблюдение → следующее действие» не более пяти шагов. Проверь связность правила: неверная ссылка исключается с причиной, корректный риск сохраняется, все неверные ссылки дают неопределённость, неразбираемый ответ даёт ошибку. Читай только названные файлы, исправь обнаруженные пробелы в ADR и планах unit/integration/E2E. Запусти доступные проверки. Записывай только реально выполненные действия и наблюдения; не заявляй о запуске будущего API.
