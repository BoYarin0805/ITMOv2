# Спецификация логики избранного

Контекст логики подготовлен отдельно от контекста UI. Итог согласован до реализации.

## Данные и инварианты

Ключ `weather.favorites.v1`. Конверт `{version:1,cities:[{id,name,latitude,longitude}]}`.
ID: числовые координаты, округлённые до 4 знаков и соединённые запятой.
Отрицательный ноль нормализуется. Исходные координаты сохраняются для погодного API.
Имя — непустая строка до 200 символов, может включать регион и страну.
Широта -90…90, долгота -180…180, только конечные числа без boolean и строк.

## Операции

- Загрузка не записывает данные. Неверный конверт/версия: пустой список + предупреждение.
  В корректном конверте некорректные записи пропускаются, первые 5 уникальных
  корректных записей сохраняются; возвращается предупреждение о восстановлении.
- Добавление проверяет место независимо от успешности погодного запроса.
  Дубликат и шестое место не меняют список или порядок. Результат: `duplicate`/`limit`.
- Удаление по ID не меняет текущий город, погоду или прогноз.
- Сначала меняется список сеанса, затем выполняется сохранение. Сбой записи
  возвращает `persistent:false` и предупреждение, а не откатывает действие молча.
- Следующее пользовательское изменение может восстановить успешную запись.

## Проверка

Модуль тестируется без сети с обычным и ошибочным storage-adapter. Проверяются
лимит, дедупликация, -0, неверные координаты, повреждённый JSON, неверная версия,
запрет чтения/записи и отсутствие записи при чтении.

## Изменения после согласования UI

Зафиксированы точность ID, комбинированное name, session-first поведение,
сохранение корректных отдельных записей и добавление до ответа погодного источника.
