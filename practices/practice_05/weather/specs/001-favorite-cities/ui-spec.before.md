# Избранные города: исходная спецификация UI

Контекст «команда интерфейса». Подготовлено до реализации отдельно от спецификации
логики. Это исходный вариант для согласования общего контракта.

## Цель

Пользователь сохраняет до пяти городов, быстро переключается между ними и удаляет
ненужные записи. Избранное дополняет поиск и готовые города, не подменяет погоду.

## Экран и действия

1. В разделе выбора города есть кнопка «В избранное» для выбранного города и список
   сохранённых городов. При отсутствии корректно выбранного города кнопка недоступна.
2. Пустой список имеет подпись «Пока нет избранных городов» и подсказку выбрать город.
3. В каждой записи есть отдельные действия выбора и удаления. Название и доступные
   регион/страна позволяют отличить одноимённые города.
4. Выбор записи использует тот же загрузчик текущей погоды и прогноза, что обычный
   выбор города. Видимый выбор города обновляется сразу; ошибки источника показываются
   существующими сообщениями, список избранного не исчезает.
5. Удаление убирает только запись из избранного. Если этот город сейчас открыт,
   текущая карточка, прогноз и выбранный город сохраняются.

## Пограничные состояния

- Повторное добавление того же места не создаёт вторую запись. Подпись:
  «Город уже в избранном»; порядок списка не меняется.
- Шестой уникальный город не добавляется. Подпись: «Можно сохранить до 5 городов.
  Удалите один из списка»; существующие записи не меняются.
- Если браузер не разрешает хранение, действия продолжаются в памяти вкладки.
  Явная подпись: «Хранилище недоступно: избранное сохранится только до перезагрузки».
- Повреждённая запись/структура хранилища не ломает поиск и погоду. Интерфейс сообщает
  о восстановлении/пропуске повреждённых данных, а не заявляет об успешном сохранении.
- Сбой сохранения при добавлении или удалении не скрывается сообщением успеха.
  Точный порядок применения изменения к памяти и сохранению согласуется с логикой.

## Доступность

Все действия — настоящие кнопки с видимым фокусом, доступны Tab и Enter/Space.
Кнопка удаления имеет название «Удалить [название города] из избранного».
Список не вложен в другую кнопку; удаление не должно одновременно выбирать город.
Результат добавления/удаления/ошибки объявляется через `role=status`/`aria-live`.
После удаления фокус остаётся в доступном месте списка либо на кнопке добавления.

## Сценарии приёмки UI

| Вход/действие | Ожидаемый видимый результат |
| --- | --- |
| Первый вход | Пустое состояние; поиск и текущая погода работают |
| Добавление выбранного города | Одна подписанная запись и сообщение результата |
| Повтор по тем же координатам | Дубликата нет независимо от написания имени |
| Шестой уникальный город | Сообщение лимита; первые пять сохранены |
| Выбор избранного | Выбор города и погодные данные соответствуют записи |
| Удаление открытого города | Запись удалена; текущая погода остаётся |
| Запрет localStorage | Явное предупреждение; можно работать до перезагрузки |
| Повреждённый localStorage | Понятное предупреждение; интерфейс не падает |
| Только клавиатура | Можно добавить, выбрать и удалить запись |

## Контракт для согласования с логикой

Предлагаемая запись: `{name, latitude, longitude, region?, country?}`.
Регион/страна необязательны: текущий загрузчик может уже вернуть составное `name`.
Идентичность определяется координатами, а не текстом названия; предложена нормализация
до четырёх знаков после запятой. Требуется договориться о точной схеме localStorage,
версионировании, кодах результата операций и восстановлении повреждённых записей.

До согласования контракта код интерфейса по этой спецификации не реализуется.
