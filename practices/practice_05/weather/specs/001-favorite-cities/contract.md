# Общий контракт UI ↔ логика (до кода)

1. Одна модель: `{id,name,latitude,longitude}`; имя уже пригодно для отображения.
2. Ключ `weather.favorites.v1`, конверт version=1. ID по координатам toFixed(4),
   отрицательный ноль → 0. Координаты запроса не округляются.
3. До 5 мест; повтор сохраняет порядок и количество; шестое не добавляется.
4. Выбранное местоположение существует независимо от погоды. Можно добавить его
   сразу, не дожидаясь сети. Выбор избранного вызывает обычный загрузчик города.
5. Ошибка хранения не ломает UI: список работает в памяти, предупреждение явно
   говорит о потере после перезагрузки. Загрузка повреждённых данных не перезаписывает их.
6. Удаление не меняет текущую погоду; фокус после удаления возвращается на кнопку добавления.
7. Из UI выводятся текстовые значения через textContent, никаких HTML-вставок из хранения.

## Разбор расхождений

UI изначально предлагал region/country; логика — готовое name: принят единый name.
Точность идентичности отсутствовала: приняты 4 знака, исходные координаты сохраняются.
Ошибка записи могла означать откат либо изменение сеанса: согласован session-first.
Независимый UI-контекст: `ui-spec.before.md` → `ui-spec.md`.
Контекст логики: `logic-spec.before.md` → `logic-spec.md`.
Согласование зафиксировано до реализации favorites.js; дальнейшее исполнение
разрешено общим поручением пользователя на завершение работы.
