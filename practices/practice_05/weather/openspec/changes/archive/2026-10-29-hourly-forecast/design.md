# Design

## Context

Существующий сервер стандартной библиотеки Python и vanilla JS получают текущую
погоду по координатам. `weatherState` уже преобразует WMO-коды. Мотивация — proposal.md.
Изменение затрагивает внешний источник, API и состояние интерфейса, поэтому нужен design.

## Goals / Non-Goals

**Goals:** изолировать отказ прогноза, использовать один контракт для всех городов,
сохранить идентичность запроса при гонках, не зависеть от зоны устройства.
**Non-Goals:** хранение погоды, авторизация, недельный прогноз, изменение MCP-контракта.

## Decisions

1. Отдельный `/api/forecast` с теми же параметрами города, что у `/api/weather`.
   Альтернатива — общий ответ — связывала бы доступность текущих данных и прогноза.
2. Open-Meteo: `hourly=temperature_2m,weather_code,is_day`, `current=temperature_2m`,
   `forecast_days=3`, `timezone=auto`, `timeformat=unixtime`. Сервер проверяет типы,
   значения, порядок и длины массивов, затем отбирает 24 часа относительно
   Unix `current.time` из этого ответа.
   Нулевые значения не используются для заполнения пропусков.
3. Unix время нормализуется через Python `zoneinfo` в локальные ISO-строки с UTC-offset.
   В JSON возвращаются эти строки, зона и координаты. JS выводит строковые
   компоненты даты без `new Date(localTime)`, чтобы зона устройства не смещала часы.
4. Отдельный счётчик запросов прогноза. При смене города прогноз очищается сразу,
   ошибки и спиннер отделены от текущих условий. Режимы live/forecast/demo взаимоисключаются.

## Risks / Trade-offs

- [Переход DST может повторить локальное время] → проверять шаг 3600 в Unix времени,
  сохранять локальный UTC-offset, не дедуплицировать повторный час; отображать дату и зону.
- [Три дня больше нужного] → один небольшой запрос на город, отображаются только 24 записи.
- [Разные времена обновления текущих условий и прогноза] → отдельно подписать время
  данных и источник; не называть прогноз измерением.

## Migration Plan

API добавочный. Запуск прежней командой; при откате убрать новую панель и маршрут,
не меняя текущую погоду, поиск, файлы пользователя и структуру хранилища.
